# Afghanistan Business Ledger

A mobile-friendly installable web app for daily business records. Users may create accounts, but database row-level security blocks all business data until the owner approves them.

## What is included

- Email/password signup and login
- Owner approval or rejection of new users
- Daily sales, purchases, expenses, other money in/out, closing cash, and notes
- Database-calculated expected closing cash and cash difference
- Monthly and quarterly summaries
- Owner access to every record and user
- Installable PWA for Android, iPhone/iPad, and desktop
- Supabase Row Level Security on every public table

## 1. Create and configure Supabase

1. Create a project at [Supabase](https://supabase.com/dashboard).
2. Open **SQL Editor**, paste `supabase/migrations/001_initial_schema.sql`, and run it.
3. In **Authentication → URL Configuration**, set **Site URL** to your eventual deployment URL. While testing locally, add `http://localhost:5173` to Redirect URLs.
4. In **Authentication → Providers → Email**, keep email/password enabled. Email confirmation is recommended. For dependable production delivery, configure custom SMTP.
5. In **Project Settings → API**, copy the Project URL and the **publishable** key. Never put a secret/service-role key in this app.

The migration includes explicit Data API grants because new Supabase projects may not automatically expose newly created tables.

## 2. Run locally

```sh
cp .env.example .env
```

Put your Project URL and publishable key into `.env`, then:

```sh
npm install
npm run dev
```

Create the owner's account through the app. Then run this once in Supabase SQL Editor, using the owner's real email:

```sql
update public.profiles
set role = 'admin', status = 'approved'
where email = 'OWNER_EMAIL_HERE';
```

Log out and back in. The owner will now see **Users** and can approve accounts.

## 3. Deploy from a link

### Recommended: Vercel

1. Put this folder in a private GitHub repository (OneDrive alone is storage, not web hosting).
2. Import the repository at [Vercel](https://vercel.com/new).
3. Add environment variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`.
4. Keep build command `npm run build` and output folder `dist`, then deploy.
5. Put the final `https://...vercel.app` address into Supabase **Site URL** and **Redirect URLs**.

Netlify or Cloudflare Pages also work: build with `npm run build` and publish `dist`.

## 4. Install on a phone

- **Android/Chrome:** open the link, open the browser menu, choose **Install app** or **Add to Home screen**.
- **iPhone/iPad/Safari:** open the link, tap **Share**, then **Add to Home Screen**.
- **Computer/Chrome or Edge:** use the install icon in the address bar.

The app shell can open like an installed app. Entering or reading business data still requires an internet connection so Supabase can enforce permissions and save safely.

## Operating notes

- A new signup is always `pending`; it cannot read or add business data.
- Approved users can read reports and add entries. They can update only their own entries at database level; the owner can update/delete all entries.
- The owner can approve/reject users. Promote another administrator only when necessary.
- Calculated columns are generated by Postgres and cannot be overwritten by the browser.
- Before production use, test with three accounts: owner, approved worker, and pending worker.
